ISO 13485 文件预筛平台使用手册

适用对象：本地使用人员及项目维护人员

版本 1.0　编制日期 2026年11月23日

本手册根据当前项目代码和本机配置编写，帮助你启动网页、上传文件、理解预筛结果，以及维护 MySQL 和服务端口。建议先完成一次文件预筛，再阅读配置与排错章节。

1 快速使用

1. 在浏览器打开 http://127.0.0.1:5300 。若不能打开，按第 2 章启动服务。

2. 输入管理员邮箱 admin@example.com 和此前单独提供的密码，点击“登录工作区”。手册不保存密码、数据库凭证或服务端密钥。

3. 点击“浏览文件”或拖入文件，为每份文件选择正确的文件类型。

4. 点击“开始预筛”，等待显示“预筛完成”，查看得分、待核实项、文本证据和建议。

5. 对照原始文件人工复核；再次检查可点击“新建预筛”。使用结束后点击“退出登录”。

2 启动和停止服务

已安装依赖的本机按以下顺序启动：MySQL、后端、前端。保持前后端终端窗口打开。已能访问网页时，不必重复启动，也无需再次初始化数据库。

Windows PowerShell

检查 MySQL；仅在服务停止时启动，启动服务可能需要管理员终端：

Get-Service MySQL84
Start-Service MySQL84

在第一个终端启动后端，使用项目已有的 Python 3.12.10 虚拟环境：

Set-Location D:/iso/backend
./.venv/Scripts/python.exe Run.py

在第二个终端启动前端，沿用 Node.js 26.13.1：

Set-Location D:/iso/frontend
npm.cmd run dev

打开 http://127.0.0.1:5300 。后端状态地址为 http://127.0.0.1:8300/api/v1/health ，正常时返回 code 为 0、status 为 ok。此接口只确认应用存活，不检查 MySQL；数据库故障应另查连接。

macOS 与 Ubuntu

将下面的 /path/to/iso 换成实际项目目录。数据库服务的启动命令取决于安装方式；Ubuntu 常见为 sudo systemctl start mysql，macOS 使用对应安装工具提供的服务命令。不要照搬 Windows 服务名。

cd /path/to/iso/backend
./.venv/bin/python Run.py

另开终端执行：

cd /path/to/iso/frontend
npm run dev

停止与重新启动

前台启动的服务在各自终端按 Ctrl+C 停止，再执行原命令启动。后台服务须先按端口确认进程归属，再停止本项目进程。MySQL 可能供其他项目使用，不要随网页停止而随意关闭它。Vite 开发服务适合本地使用；Ubuntu 正式部署按 deploy.md 操作。

3 上传文件并执行预筛

准备文件

支持 PDF、DOCX、XLSX、TXT、MD；本机单文件上限为 40 MB，一次预筛提交 1 至 20 个不重复文件。PDF 应能选中文字；扫描件、纯图片和加密文件可能无法解析。可抽取文本少于 60 个字符时会被拒绝。

旧版 DOC、XLS 需另存为 DOCX、XLSX；WPS、ET 需导出为支持格式。直接修改文件扩展名不能完成格式转换。TXT、MD 建议使用 UTF-8 编码。

实际操作

1. 登录后进入“文件预筛”，点击“浏览文件”，或把文件拖入上传区域。

2. 检查文件名及大小。相同文件名且大小相同的文件会在队列中被视为重复；超过 20 份请分批操作。

3. 为每份文件选择类型。默认是“其他体系文件”，系统不会自动替你选好类别。类型会影响参与判定的专用规则。

4. 移除误选文件可点击对应行的“×”。确认后点击“开始预筛”，系统先逐份上传与抽取，再执行规则。

5. 看到“预筛完成”后查看结果。处理失败时按错误提示调整，再操作；不要把未完成状态当作成功结果。

修改后重新预筛

文件一旦显示“已解析”，再次点击“开始预筛”会复用已上传文件及其类型。若修改了文件内容或需要更换已上传文件的类型，请点击“新建预筛”，重新添加文件并选择类型后提交。

“移除文件”和“新建预筛”只清空本次页面队列或结果，不会删除数据库记录及已上传原件。刷新或退出页面后，当前网页没有历史列表可重新打开结果，重要信息请先另行记录。

4 结果和规则包说明

如何读结果

“通过”表示在抽取文本中找到规则要求的线索；“待核实”表示未命中相应条件，需要核对原文或补充内容；“未适用”通常表示本次没有上传该专用规则适用的文档，不代表已证明标准条款可以排除。

“参与规则”是实际判定项数量，多文件时同一规则可以产生多项结果。“未适用”不进入得分分母。先查看“待核实”项目，再结合文件名、条款、文本证据和建议定位原文。

当前 8 条规则

规则包文件：D:/iso/backend/App/Rules/core.json。标识为 iso13485-core，版本为 1.0.0，包内标注标准为 ISO 13485:2016。下表是项目规则摘要，不是标准原文。

编号适用文件检查线索
DOC-001所有类型文件编号
DOC-002所有类型版本或修订标识
DOC-003所有类型批准或授权字段
DOC-004所有类型生效或发布日期字段及日期格式
QMS-001质量手册范围及产品或医疗器械概念
MR-001管理评审评审输入与输出或措施
AUD-001内部审核审核发现与纠正或跟进
RISK-001风险管理风险分析 风险控制 剩余风险

前 4 条中 DOC-004 是“一般”级，其余当前规则为“主要”级。规则多以正则或词组匹配判定，不审核签名真实性、日期有效性或文件实际执行情况。DOC-004 检查字段与文本形式，不等于审核日期逻辑。

得分怎么计算

基础分为通过项权重之和除以参与项权重之和，再乘 100；当前“主要”权重 5，“一般”权重 2。有主要待核实项时，得分上限为 75。引擎还支持严重级别及 45 分上限，当前包尚未使用该级别。

页面结论来自内部评分：无严重项且得分至少 90 并无主要待核实项时显示“符合”；否则得分至少 75 为“基本符合”，至少 60 为“需整改”，更低为“不符合”。这些名称只描述当前规则结果，即使 100 分也不能据此宣布体系符合标准。

在哪里查看说明

左侧“规则说明”和右侧“查看规则包说明”目前都只滚动到“使用说明”，没有独立规则明细页。完整条件需查看 core.json；修改前备份并提升规则版本，在测试环境验证后重启后端。

5 配置 MySQL 和服务端口

两份环境文件

后端配置：D:/iso/backend/.env。前端配置：D:/iso/frontend/.env.development。修改前先安全备份；这些文件不提交 Git。保留原有加密密钥和 JWT 密钥，不要为修改端口而重新生成它们。

文件字段本机当前值或用途
后端 .envDATABASE_URLMySQL 连接串
后端 .envBACKEND_HOST127.0.0.1
后端 .envBACKEND_PORT8300
后端 .envFRONTEND_PORT5300 用于配置对齐
后端 .envCORS_ORIGINS允许访问的前端来源
前端环境文件FRONTEND_PORT5300 实际网页端口
前端环境文件VITE_API_BASE_URLhttp://127.0.0.1:8300

MySQL 连接串

以下仅为格式示例；不要直接覆盖已配置的真实密码：

DATABASE_URL=mysql+pymysql://账号:密码@主机:端口/库名?charset=utf8mb4

当前主机为 127.0.0.1、端口为 3306、库名为 iso13485。密码含 @、#、: 等字符时必须 URL 编码。修改连接串只改变应用连接目标，不会创建数据库、修改 MySQL 账号或更改数据库服务端口。

使用 MySQL Workbench

打开 Workbench，新增连接，选择 Standard TCP/IP，Hostname 填 127.0.0.1，Port 填 3306，Username 填项目数据库账号 iso_user。密码使用后端 .env 中 DATABASE_URL 的密码部分；若做过 URL 编码，应还原后输入。测试连接成功后选择 iso13485。网页管理员邮箱及密码不能用于登录 MySQL。

更换端口的例子

将网页端口从 5300 改为 5310：修改前端 FRONTEND_PORT、后端 FRONTEND_PORT，并将后端 CORS_ORIGINS 中允许的网页来源端口一并改为 5310，重启前后端后访问新地址。

将后端从 8300 改为 8310：修改后端 BACKEND_PORT，以及前端 VITE_API_BASE_URL 的端口，再重启前后端。更改 MySQL 监听端口需先调整数据库服务配置并重启 MySQL，再更新 DATABASE_URL；Windows 本机服务指定配置文件为 C:/Program Files/MySQL/MySQL Server 8.4/my.ini。macOS 和 Ubuntu 路径按安装方式确认。

本地网页建议始终使用 127.0.0.1；不要一端用 localhost、另一端用 127.0.0.1，以免 Cookie 跨站限制影响登录。测试前后端规划使用 5400、8400，正式使用 5500、8500；测试库必须独立，不能用正式库测试。

6 账号和数据维护

管理员账号

本机已有管理员 admin@example.com。网页尚未提供注册、账号管理或修改密码页面。新增管理员须由可信维护人员在后端目录使用交互脚本，输入有效邮箱、显示名称和至少 8 位且含字母与数字的密码。

Windows PowerShell：

Set-Location D:/iso/backend
./.venv/Scripts/python.exe CreateAdmin.py

macOS 与 Ubuntu 在实际 backend 目录运行：

./.venv/bin/python CreateAdmin.py

同邮箱已存在时脚本会拒绝创建，不会重置旧密码。忘记密码请交由维护人员处理，不要直接将数据库中的密码哈希替换为明文。管理员和审核员可上传及预筛；其他角色不能执行写入。

初始化与版本维护

InitDb.py 只用于已确认的空开发库或测试库，创建缺失表，不会升级已有表。当前本机已初始化，不需日常重复运行。结构升级应使用经测试库验证的迁移，不通过删库重建解决问题。

本机已验证虚拟环境为 Python 3.12.10，Node 为 26.13.1；当前 backend/.python-version 写的是 3.15，与虚拟环境和 README 不一致。维护时沿用现有 .venv，不按该文件盲目升级解释器；版本声明统一需单独处理。

当前界面还没有模型配置、历史记录查询、报告导出或服务配置页面。MySQL 和端口需改环境文件；预筛使用规则引擎，不需要填写大模型 API Key。

7 常见问题和排查顺序

网页打不开

先检查地址是否为 http://127.0.0.1:5300 ，再确认前端终端在运行。修改过端口要使用新地址。端口占用时先确认进程，不要直接结束陌生进程。

Windows 查看监听情况：

Get-NetTCPConnection -State Listen -LocalPort 5300,8300

macOS 查看单个端口；查询后端时将 5300 改为 8300：

lsof -nP -iTCP:5300 -sTCP:LISTEN

Ubuntu 对应查询：

ss -ltnp 'sport = :5300'

网页能打开但无法登录

先核对邮箱和密码，再检查后端是否运行。若健康接口正常，仍需检查 MySQL84 服务及 DATABASE_URL，因为健康接口不验证数据库。Access denied 通常表示 MySQL 账号、密码或匹配主机权限不正确；Connection refused 通常表示服务未监听目标地址和端口。

出现“数据库业务表尚未初始化”时，先确认连接的是预期库，再让维护人员处理初始化或迁移。不要向未知数据库运行建表命令。CORS 或请求失败则核对前端 API 地址及后端 CORS_ORIGINS，修改后重启。

文件不能上传或解析

确认扩展名和真实格式一致、文件未损坏或加密，大小不超过 40 MB。文本不足时先确认 PDF 可选中文字；扫描件需在平台外完成 OCR 并导出可检索文本。超过 20 份分批提交，重复文件先从队列移除。

明明有内容却显示待核实

可能是字段在图片、页眉页脚或无法完整抽取的表格内，也可能是现有规则词组未覆盖实际表述。先核对文件类型和原文，不要为追求高分添加无实际意义的关键词。由维护人员确认后再调整规则并重新验证。

登录后刷新或退出导致结果消失

这是当前界面的限制。数据可能已保存在数据库，但网页没有历史查询或报告导出功能。操作前安排好结果记录方式，不要把“新建预筛”当作删除服务器文件的操作。

反馈问题时提供什么

提供发生时间、页面错误提示、文件格式和大小、操作步骤，以及是否修改过端口。维护人员可查后端日志及响应中的 X-Request-ID。不要发送真实密码、完整 Cookie、数据库连接串或完整 .env；涉及敏感文档时先脱敏。
