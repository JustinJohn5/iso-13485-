# 整套手册与规则手册设计

日期：2026-11-24。用户已确认同时支持导入、生成，并以整套发布版本号归档。

## 工作流程

新增“整套手册”工作区。同一组织/项目的套册名称加发布版本组成独立档案；
文件自身版本、规则包版本及 ISO 标准版本分别保存。允许分批补充、删除误加成员、
修改成员的目录归属及文件版本。保存操作使用修订号，过期操作整体拒绝。

新建档案后可选择体系目录批量生成，也可导入既有支持格式的文件，两者共存。
生成沿用项目的参数校验与 Word 排版，按明确列出的示例目录提供质量手册、
方针目标、程序和记录框架。用户按自身适用范围选择目录，不宣称自动覆盖所有法规。
生成件保留待填写与待批准信息，不编造组织事实、技术限值或执行记录。
生成正文可按章节修改，要求记录变更原因；同一套册不提供历史操作修订恢复，
发布历史应建立独立整套版本保留。

每套最多100份文件。导入沿用既有上传和解析接口，归档时批量核对文件权限，
冻结抽取正文及元数据。生成正文和导入抽取正文都可在线阅读。
按目录列出本套已提供与未提供项目；统一预筛运行项目实际规则引擎，
同时展示编号引用、版本冲突和期限冲突。冲突不会被高分掩盖。
下载 ZIP 包含生成 Word、导入原件、目录清单及已保存检查结果。
旧套册不会因新版本或编辑其他草稿而改变。

## 数据与接口

MySQL 新增 manual_suites 表，保存用户、名称、版本、唯一归档标识、修订号、
成员 JSON 快照、最新检查快照及时间。新增表同时纳入初始化与显式迁移。
列表只读取摘要列，支持分页、名称查询和版本精确过滤；详情按用户权限读取。
新增 /api/v1/manual-suite-catalog、/manual-suites 及成员、生成、检查、下载子资源。
所有读取和写入检查所属用户；管理员依照既有项目规则可访问已知档案。
成员变动会清空当前检查结果，避免旧结果描述新文件。并发变更使用数据库条件更新。
目录查询不访问数据库；归档查询一次批量取文件，写套册一次，不在循环中查询。

规则手册增加 /api/v1/rule-sets/{id}，直接返回已加载规则包。
页面按规则版本、条款、适用类型检索，展示编号、判定条件、依据及建议，
与运行引擎使用同一来源。默认登录后可访问，不增加匿名文件访问。

## 验证与交付

测试覆盖版本独立、重复版本、并发拒绝、批量生成及真实 Word/ZIP、
分批导入、目录缺项、成员校正、检查失效、权限隔离和规则阅读。
E2E 使用既有 MySQL 8.4 _codextest 副本，清理仅限临时账号数据。
沿用 Python 3.12.10、Node.js 26.13.1，无新增运行依赖及部署环境变量。
更新 README、deploy.md、CHANGELOG.md、tests/README.md，分别提交功能。
