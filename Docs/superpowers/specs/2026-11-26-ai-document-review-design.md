# ISO 13485 AI 文件审阅设计

## 目标

让 AI 参与现有 ISO 13485 文件预筛后的阅读工作，提供两种明确区分的辅助方式：

1. **AI 查找依据**：针对一个检查项和用户选定的一份文件，查找可能相关的支持、反向或待核实原文。
2. **AI 逐项审阅**：按该检查项拆分出的必需要素，逐项整理支持线索、相反表述、当前片段未找到的内容和人工追问。

两种方式都只生成候选意见，不生成符合、不符合或认证结论，不修改规则预筛状态、覆盖率或分数。

## 使用流程

用户完成现有预筛后，在结果页选择检查项和本次预筛中的一份文件，再选择“查找依据”或“逐项审阅”。系统按当前规则与文件内容检索相关片段，将检查项、必需要素、文件用途、规则状态和有来源位置的文本片段提交给现有 OpenAI 兼容客户端。页面展示 AI 建议、模型名称、原文摘录和抽取文本行号。

用户可确认采纳、修改后采纳或驳回。每次决定记录操作人、时间、决定类型和理由；原始 AI 输出继续保留。用户刷新前可在本次结果页面查看分析；API 提供按预筛任务读取已有 AI 审阅结果的能力。

## 证据与审阅规则

- 检索范围限定为预筛任务已纳入的文件，且由请求者拥有或由管理员访问。
- 每次请求针对一个规则和一份文件，避免将不同对象、版本或产品的内容拼成同一证据链。
- 先用规则必需要素、同义词、标题及邻近文本生成候选片段，再由模型阅读和解释候选片段；AI 查找结果不声称已穷尽全文。
- 模型引用必须包含候选片段标识和原文摘录。后端验证摘录确实出现在对应片段中；不匹配的引用不作为证据展示。
- 逐项审阅仅能给出“支持线索”“反向线索”“片段中未找到”“待补信息”“需人工核实”等候选状态。“片段中未找到”不能被解释为整份文件缺少要求。
- 文件文本抽取不完整时随结果显示警示；扫描页、图片和未抽取内容不能交给模型推断。
- 文件内容视为不可信数据，不能覆盖系统提示、规则、权限或输出格式要求。
- 模型未配置、调用超时、响应 JSON 无效或证据无法校验时，明确报错或标记未核实；不影响已有规则结果。

## 数据与接口

- 复用管理员网页配置的模型和 `App.Services.Llm.Client.complete_json`；不新增大模型环境变量、依赖或数据库。
- 新增 MySQL AI 审阅记录，保存预筛任务、请求者、模式、条款、文件、规则版本、模型名称、已校验的分析结果、耗时和人工决定历史；不保存 API Key、完整提示词或整份重复正文。
- `POST /api/v1/validations/{run_uid}/ai-reviews` 创建一次分析，输入模式、规则编号和本次预筛中的文件标识。
- `GET /api/v1/validations/{run_uid}/ai-reviews` 读取任务所属用户可见的分析及决定历史。
- `PATCH /api/v1/ai-reviews/{review_uid}/decision` 追加采纳、修改采纳或驳回记录。
- 结果以 JSON 保存；不写回 `Finding`、覆盖率或预筛分数。

## 验收标准

1. 两种模式均使用网页管理的 OpenAI 兼容配置；未配置时返回明确错误，不使用隐藏默认值。
2. 两种模式均限制在本次预筛文件和一个文件对象内，且跨用户访问被拒绝。
3. 所有展示的证据摘录均可在对应抽取文本中精确找到，并显示文件标识和抽取行号。
4. 模型输出必须符合各模式的结构；未知检查项、伪造摘录、未知字段或不完整子检查均拒绝保存。
5. 每次人工决定追加保存，能够读回并区分先前决定；原始 AI 输出不被覆盖。
6. AI 分析及人工决定不改变规则预筛结果、覆盖率和分数。
7. 单元测试不调用外部模型；E2E 使用仅监听回环地址的测试用 OpenAI 兼容服务，并只连接 `_codextest` MySQL。

## 明确不包含

- 自动判断 ISO 13485 符合、不符合或认证通过。
- 自动批准不适用或设计删减。
- 全文件、全体系的无人值守批量审计。
- OCR、原件页码/表格单元定位升级、向量数据库或新增模型服务商 SDK。
