# ISO 13485 文件预筛规则

编制日期：2026-11-24。文档版本：1.1。已接入文件预筛、套册检查和模拟内审。

`iso13485-core` 2.0.0 按当前范围运行。抽取行用于定位原文，重复证据保留代表片段。系统对明确编号的引用核对所选文件、版本和文本。扫描页、图片内容以及无法可靠比较的引用和保存期限列入待补或人工核实。

与[规则总则](Iso13485Rules.md)、[条款矩阵](Iso13485ClauseMatrix.md)共同使用。本规则规定的是目标行为，不代表现有 `core.json`、引擎或网页已更新。预筛识别所提供文件中的要求线索、信息缺口和有限一致性问题；不能证明实际执行、产品安全或体系符合。

## 1 预筛范围

提供两种明确区分的范围：

- **单份或选定文件预筛**：检查所选文件用途应承载的要求，以及其明确引用的依据。不能因为只上传一份文件就报告整套体系不完整。
- **体系文件集预筛**：依据组织范围、适用性和承载关系检查体系要求及配套记录。不是按固定 20 项目录计算完整性，未提供的证据应列明“本次未提供”。

所选范围、审核基准日、组织活动、适用性和版本依据必须纳入结果快照。若缺少体系范围，则最多完成文件级线索检查，体系覆盖显示“范围待确认”。

## 2 文件用途与检查路由

文件业务类型和文件用途分别识别。文件名、标题、关键概念只能提供分类建议，歧义或证据不足时要求人工确认。文件本身的控制字段可用于各类文件，但某次会议、试验或放行的真实记录只检查相应记录对象。

| 文件用途 | 检查重点 | 不应发生的误判 |
|---|---|---|
| 程序 | 流程、角色、条件、方法、准则和记录要求 | 因无某次实际执行数据而把程序判为记录不完整 |
| 计划 | 阶段、职责、资源、交付物、评审和追溯 | 因合法未来里程碑而判为文件无效 |
| 规程 | 操作、方法、参数依据、判定、异常及记录 | 因没有具体批次实测值而否定规程框架 |
| 报告 | 来源、对象、方法、实际事实、分析、局限和附件 | 仅有“分析”“结论”标题就算有实质分析 |
| 空白表单 | 是否具备适当字段及填写控制安排 | 把空白批准栏和结果栏算成有效批准或实测记录 |
| 已填写记录 | 具体对象、活动、日期、执行结果、责任及关联证据 | 把“按程序实施”“待填写”当成真实结果 |
| 支持资料 | 对应要求的来源和可追溯性 | 仅因不是某个固定文件名称就判缺件 |

文件所承担条款须由类型、用途、标题、适用范围和明确引用共同确认。出现“采购”“设计”等词，不足以让全文承担对应全部条款。质量手册可以概述并引用程序，不要求复制所有操作细节。

## 3 判定状态

| 状态标识 | 中文展示 | 触发条件 | 对覆盖的影响 |
|---|---|---|---|
| `evidence_found` | 已检出要求线索 | 需要的要素有上下文证据，文件用途正确，无相应未解决冲突或占位 | 仅说明文本线索满足本检查 |
| `gap` | 未检出要求线索 | 已知适用且应承载的要素，在本次可读资料及明确引用中未检出 | 计为文本缺口，不直接定性不符合项 |
| `pending_input` | 信息待补充 | 待填项、未确认事实、必要引用未提供，或适用条件未知 | 不作为已检出；提示补充事项 |
| `conflict` | 内容冲突待核对 | 同一对象、同一适用上下文存在不能同时满足的明确陈述 | 保留双方证据，优先显示冲突 |
| `unreadable` | 文本无法判定 | 扫描、损坏、抽取失败、关键表格或图片内容无法识别 | 不判为内容不存在，也不算已检出 |
| `manual_review` | 需人工核实 | 真实性、有效性、复杂语义、来源疑点或现有能力无法决定 | 标明取证问题，不伪造自动结论 |
| `not_applicable` | 不适用且已确认 | 有合格的不适用理由和授权确认记录 | 从适用检查分母中排除并单列 |
| `out_of_scope` | 本文件不承载 | 该要求不应由此文件承载，或不在本次文件级范围 | 不代表组织不适用，单列范围说明 |

一个条款可以包含多条子检查，各子检查分别保留状态；不得因某一要素命中就覆盖其他缺口。条款汇总同时展示各状态数量及关键问题，不把所有“非失败”都并入通过。

当同一子检查命中多种情形，先确认适用性和文件路由；未知适用性列为待确认。对已知适用对象，无法读取先保留无法判定，明确冲突优先于正向命中，待填和缺口不能被其他段落的泛化关键词掩盖；真实性核实可与文本线索状态并列保留。

## 4 证据规则

### 4.1 什么算可用线索

| 线索类型 | 处理 |
|---|---|
| 仅标题、目录或字段名称 | 可证明标题或字段存在，不能证明对应流程已规定或活动已完成 |
| 程序中的职责、触发、步骤和准则 | 可支持制度安排的检查；不证明实际执行 |
| 记录中的对象、日期、结果、执行人及附件关联 | 可支持记录完整性线索；真实性和充分性仍需人工核实 |
| 明确受控引用 | 能定位编号或明确索引、适用版本和目标内容时，可与本文件共同支持要求 |
| 指向未提供文件 | 显示待提供依据，不能只凭引用词认定目标内容存在 |
| “待填写”“待确认”“示例”“XXX”“某某”等 | 结合上下文识别占位；若承担必需事实则为待补，不简单全篇禁词 |
| “已满足所有要求”“按规定执行” | 不作为相关全部要素的替代证据 |
| “未进行调查”“无需审批”等否定陈述 | 保留完整句和例外条件；不能因命中“调查”“审批”算已检出 |

“不允许未经批准放行”属于控制要求，不能因含“不”“批准”就误报缺少批准。否定、条件、例外或双重否定解释不可靠时，使用人工核实状态；不做简单黑名单替代语义判断。

### 4.2 要素组合

1. 以矩阵列出的要求概念拆成必需要素组，同组同义表达可互换，不同必需组不能互相抵扣。不预设“命中任意两组就通过”。
2. 在相关章节、表格行、同一对象的记录或有明确关系的引用中寻找证据。全篇散落的词不能随意组合。
3. 文本归一化可处理 Unicode、全角空格、换行和常见排版差异；证据仍指回未改写的抽取原文。必须保留标准单位、数值、否定词和条件。
4. 同一规范可由多个文件承载，但每个要素保留各自证据；不能把 A 产品的要求与 B 产品的记录拼为一个完整证据链。
5. 未覆盖的表达不能直接宣告要求不存在，应显示“在本次可抽取文本中未检出”并列出人工复核路径。

### 4.3 每条结果至少提供的信息

规则及子规则编号、规则版本、依据类别、条款、来源定位、适用条件、文件用途、对象、文件标识及版本、摘要、证据原文、抽取位置、命中与缺失要素、状态原因、建议、人工核实问题。

PDF 可获得可靠页边界时记录物理页及抽取段；DOCX 记录段落或表格单元；XLSX 记录工作表和单元格；纯文本记录行号。不把抽取行号伪装成原件页码，无法定位时明确说明。

结果摘要可以截短显示，原文定位及完整证据依据应可追溯；不能只保存一段无法回到原文的关键词拼接。访问原件、快照和复核决定仍须校验权限。

## 5 预筛顺序

1. **确认范围**：文件级或体系级、审核基准日、组织事实和所需活动。
2. **读取和抽取**：校验文件类型、大小和可读性，保留原件及摘要；关键内容不可抽取时显示边界，不将扫描件判为缺少流程。
3. **确认分类和用途**：识别建议可手动校正；分类不确定时避免强套专用规则。
4. **核对版本和重复**：识别同编号多版本；授权人员选择本次依据；不按版本字符串或上传时间自动选正式版。重复内容只计一次，真正不同的记录不能仅因共享模板就去重。
5. **路由适用性**：按条款条件和承载关系选择规则；外包、未知、不适用和本文件不承载分别处理。
6. **检查内容**：要素、步骤、引用、记录、日期、数值、占位、否定和来源疑点。
7. **检查关联**：针对同一对象核对编号版本、技术准则、保存期限等；能力之外的语义列为人工核实。
8. **汇总结果**：按文件、条款和对象展示线索、缺口、待补、冲突、无法判定和人工事项。
9. **保存快照**：固定本次输入、规则版本、适用性、版本选择及人工决定；后续补件必须重新检查并产生新结果。

系统出现抽取或引擎异常时明确显示检查失败和原因，保留已上传原件及既有结果；禁止返回“无问题”的成功报告。规则包无法加载、引用不合法或条件缺失时阻止使用该规则版本。

## 6 专项判定规则

### 6.1 日期与有效版本

区分编制、批准、发布、生效、计划、执行、失效和记录日期，校验真实日历值。审核基准日用于判断当时适用依据；计划中的未来时间允许存在。未来生效文件如被选为基准日正式依据，应提示版本待核对，但不能直接断言其文件内容违法。

同一编号多版本保留候选和人工决定；历史审核可选当时有效版本。不得只因版本较旧、审批图像未抽取或日期字段名称不匹配就作确定性缺陷结论。

### 6.2 批准与记录

“批准：____”“待批准”仅为字段或占位。程序写明批准流程，可满足制度安排的文本线索；真实批准仍要核对授权身份、日期和受控发布记录。电子批准或外部审批系统允许通过明确引用取证，不要求所有文件嵌入手写签名。

实际记录按用途核对对象、活动、时间、结果、执行者和关联附件；责任人姓名是否真实、数据是否追记、结果是否有效交人工取证。不能自动填名或生成签名来消除缺口。

### 6.3 保存期限

分别处理 4.2.4 作废文件和 4.2.5 记录。提取对象、文件或记录编号、期限、起算事件、对应产品寿命依据和适用法规；参照[生成规则第 7 节](Iso13485GenerationRules.md#7-保存期限的专门编写要求)。

只有对象和起算口径可比时才计算冲突。例如，已确认同一记录均从放行日起算，“至少三年”与“保存五年”可以同时满足；“至少三年”与“保存一年并销毁”存在明确冲突。未知寿命期或法规时，即使写了“两年”，也不能显示保存要求已经完整。

中文数字、永久保存、复杂条件、起算点不明或多编号句不能可靠解析时，标为人工核实；不偷偷忽略。适用法规可能有专门规则，必须先确认其与标准要求的关系。

### 6.4 频次、数值和技术准则

不得将项目常用的年度内审、年度评审或固定培训周期写成标准统一时限。检查组织是否进行了适当策划及是否按其安排执行。法规报告时限、抽样量、校准周期、产品限值必须有对应依据。

跨文件对照须关联同一产品或过程、同一适用版本、相同单位与条件。不能把规格区间、最低要求、实测结果和失效阈值混作同一种值。

### 6.5 来源与模型边界

标准来源疑点按总则第 2.3 节转人工核对。若后续引入模型辅助语义分析，输出只能提供证据候选和建议；没有可定位原文不得生成“已检出”。模型不能批准不适用、覆盖已确认事实或直接判定体系符合。确定性规则和模型辅助结果应注明各自来源。

本次不新增模型预筛功能。现有大模型仍仅用于已实现的编写流程。

## 7 汇总与分数

### 7.1 结果表述

建议以“已检出线索，待实施取证”“存在文本缺口”“存在待补信息”“存在冲突，待核对”“资料无法判定”“范围或适用性待确认”显示结果。可同时出现多项，不能用一个得分把问题盖住。

不使用“符合”“基本符合”“不符合”作为自动预筛结论。问题优先级可以按影响区分为优先核对、一般补充、提示，但不称为认证审核中的严重或主要不符合项。

优先级、权重、显示顺序均是项目约定，必须公开计算口径和规则版本；矩阵不预先赋予条款统一严重等级。

### 7.2 如果保留数字指标

第一版目标采用不加权的“基础文本线索覆盖率”：

`覆盖率 = 已检出线索的检查单元数 / 已知适用且具备文本检查定义的检查单元数 × 100%`

检查单元由“子规则 + 文件用途 + 被检查对象”唯一确定。跨文件共同承载按一个目标单元计算，逐份必须保持的控制才按文件分别计算；重复上传、复制关键词不增加分子。

- 对已知适用的文本检查，待补、缺口、冲突、无法抽取均计入分母且不计入分子，不能通过删除失败文件提高完整性。
- 对适用性未知项，单列“待确认要求”；未提供组织范围时不计算体系覆盖率。
- 仅人工可判断的真实性或有效性检查单列，不纳入文本覆盖率，也不因不计分而隐去。
- 经确认不适用、本文件不承载的检查不进入本次分母，并展示数量和理由。
- 分母为零时显示“不具备计算条件”，不得显示 100 分。
- 缺少承载文件时，体系级检查仍保留该适用要求的缺口；文件级检查不扩展出未授权的全体系完整性评分。

报告同时显示适用性待确认数、待补数、冲突数、无法判定数、人工核实数和已提供范围。即使文本覆盖率 100%，也必须保留“实施与符合性需人工审核”的边界。

## 8 规则定义示例

以下为规则编制格式示例，属于文档规格，不是已加载的 JSON 规则包。

| 字段 | 管理评审输入子规则示例 |
|---|---|
| 编号 | `R-5.6.2-01` |
| 依据类别 | 标准要求 |
| 来源 | 本次资料，5.6.2，PDF 物理页 18 |
| 对象 | 管理评审程序；实际评审记录另作记录用途子规则 |
| 适用性 | 组织体系要求；具体输入若无当期事件仍需记录评价情况 |
| 必需要素 | 反馈、投诉处理、监管报告、审核、过程监测、产品监测、纠正措施、预防措施、以前跟踪、体系变更、改进建议、新或修订法规 |
| 等价表达 | 抱怨与投诉可作为术语同义词；纠正与预防不能合并成任意一个即满足 |
| 正向条件 | 程序明确规定输入范围；记录逐项列明本次输入、来源或无事项的评价说明 |
| 待补条件 | 表中仅写“待填”，或引用的输入资料未提供 |
| 缺口条件 | 已知应涵盖的输入要素未检出，列明具体要素 |
| 人工事项 | 输入是否充分、事实是否真实、是否有效参与评审 |
| 建议 | 补全缺失输入和来源；不自动生成不存在的投诉或监管报告 |

## 9 文档规则验收案例

以下均为合成场景，用于未来规则实现验证。本次仅核对规则设计，尚未编写或运行这些业务用例。

| 编号 | 输入或场景 | 预期结果 |
|---|---|---|
| A-01 | 文件只有目录中的“管理评审输入、输出” | 仅识别标题；实质输入输出未检出，不显示完整 |
| A-02 | 空白记录写“批准：____；结果：待填写” | 表单可检查字段；批准和执行证据为待补 |
| A-03 | 程序明确规定授权批准，引用实际审批流程 | 制度线索可检出；真实批准需查实际记录 |
| A-04 | “无需调查投诉”且没有理由或例外依据 | 保留否定原句，提示缺口或人工核实，不以“调查”命中通过 |
| A-05 | “不允许未经批准放行” | 识别为控制安排；不按否定词黑名单误报 |
| A-06 | 记录称本次投诉未调查，并附具体理由和审核 | 理由线索已检出；合理性及授权人工核实 |
| A-07 | 普通非无菌产品，已确认无菌专用不适用 | 相关专用要求单列不适用；一般污染控制仍按活动判断 |
| A-08 | 无菌或植入属性未确认 | 适用性待确认，不跳过也不直接判缺少灭菌记录 |
| A-09 | 委托外部灭菌 | 仍核对外包控制、质量协议及适用灭菌要求 |
| A-10 | 只写“不设计”，无适用法规允许删减依据 | 设计删减待确认，不能自动排除 7.3 |
