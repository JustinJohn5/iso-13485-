# ISO 13485 文件预筛平台

本项目提供一个基于浏览器的质量体系文件文本预筛工具。用户登录后可上传 PDF、DOCX、XLSX、TXT、MD 文件，自动识别或手动修正文件类型，并查看规则命中、可检索证据和建议。

预筛仅识别当前规则包中的文本线索，不代表文件内容真实、过程有效、体系符合标准，也不构成认证、审核结论或法规符合性声明。扫描件和图片型 PDF 暂不做 OCR。

## ISO 13485 规则重订文档

文本生成和文件预筛共用 `iso13485-core` 2.0.0 的 72 项条款目录。模板、整套生成和 AI 辅助编写会在草稿中保存条款依据及待补事项。预筛支持按所选文件或组织体系检查，显示适用条件、证据位置、文本缺口和人工核实项。相关说明见[规则总则](Docs/Iso13485Rules.md)、[文本生成规则](Docs/Iso13485GenerationRules.md)、[文件预筛规则](Docs/Iso13485PrescreenRules.md)和[条款矩阵](Docs/Iso13485ClauseMatrix.md)。

## 已完成的基础

- 账号注册与改密：仅这两个操作需要邮箱验证码。注册页发送并输入验证码后创建普通使用账号；登录只用邮箱和密码。登录后可在“修改密码”中验证当前密码和账号邮箱验证码，成功后所有旧会话失效。验证码使用 SMTP TLS 投递，MySQL 只保存验证码与来源 IP 的 HMAC 摘要；每邮箱每用途每小时最多5封，每来源 IP 每小时最多20次请求。公开接口不回显邮箱是否已注册。需配置后端邮件环境变量，并先验证 `MigrateEmailVerification.py`；操作见 `Docs/UserGuide.md`。

- 个人中心与管理后台：右上角账户菜单提供已上传文件、文件分组和修改密码；管理员可进入 `/admin/` 查看匿名与登录访客在线数、今日访问量及最近活跃时间，管理模型配置、筛选服务日志和查看操作记录。个人文件只显示本人上传记录，分组删除不会删除原件。既有 MySQL 8.4 数据库先在 `_codextest` 验证 `MigratePersonalFiles.py`、`MigrateAdmin.py`，再按 `deploy.md` 迁移开发库；无新增环境变量或依赖。

- 规则手册：登录后通过主导航或预筛侧栏查看实际执行的规则包，按关键词、条款或文件类型筛选。新版覆盖率按适用检查单元计算，每个单元权重相同。

- 整套手册：导入与批量生成统一按整套发布版本归档，20项示例目录、分批补件、正文查阅与编辑、目录校正、整套预筛及 ZIP 下载；支持100份文件、独立文件版本、并发保护及权限隔离。操作见 [整套手册](Docs/ManualSuites.md)。已有数据库需先按 `deploy.md` 验证并运行 `MigrateManualSuites.py`。

- 模拟内审：预筛完成后可生成并下载问题清单，按规则缺项、引用待核对、跨文件冲突和实施取证组织原文依据、审核提问及建议跟进；不改变预筛分数，不将文本线索定性为不符合项。

- AI 辅助编写：管理员通过“模型配置”维护 OpenAI 兼容服务，API Key 加密且不回显；草稿中可按编写要求调用模型，生成新修订，服务失败保留原草稿。未配置时模板与预筛仍可使用。

- AI 文件阅读审核：在预筛结果中选择一条检查项和一份本次文件，可使用“查找依据”整理支持、反向和待核实原文，也可按必需要素“逐项审阅”。所有引用由服务端逐字校验并显示抽取行号；采纳、修改后采纳和驳回均追加留痕，不改变预筛得分或覆盖率。沿用网页模型配置，需在 MySQL 8.4 上应用 `MigrateAiReviews.py`。

  审阅面板会检查模型状态，未配置时提示联系管理员；记录读取失败后可点击“重新检查并加载记录”恢复。若提示数据库结构未升级，先按 `deploy.md` 完成该环境的既有迁移。模型配置仅 `admin` 角色可查看和修改，普通账号使用已配置模型。

- 模板与编写：提供市场调研报告、成品检验规程、设计开发计划、文件控制程序4种自有示例模板；支持检索、参数化生成、正文修改、Word统一排版导出及50次草稿修订历史。可选择最多20份草稿，预览并统一更新组织、项目、产品、型号，批量重新生成并保留旧修订；文件编号和文件版本分别管理。
- 既有数据库需先按 `deploy.md` 在测试副本验证 `MigrateDocumentDrafts.py`，再迁移开发库并重启后端。

- 后端：Python 3.12.10、FastAPI、SQLAlchemy 2.x、MySQL 8.4。
- 前端：原生 TypeScript + Vite，前后端独立构建，只通过 HTTP API 通信。
- 后端已有模块：安全配置、日志、密码/JWT、文件防护、PDF/DOCX/XLSX/TXT 抽取、规则判定和评分模型。
- 本次补齐：可运行 API、登录、文件上传与预筛流程、ISO 13485 基础规则包、网页工作区、单元测试、E2E 用例及部署说明。
- 识别改进：添加文件后自动解析，按文件名、正文标题及关键词识别类型；线索不足或歧义时提示人工确认，已上传类型可直接修改。
- 结果改进：各检查项展示具体命中文字，相邻同文件同条款合并展示，未适用项折叠；相同内容同类型只计分一次，不同类型提示冲突。

现已支持当前批次的编号引用、同编号版本冲突、人工正式版确认及明确保存期限对照，操作见 [关联文件与正式版本](Docs/DocumentControl.md)。预筛保存采用依据快照，候选原件保留；完整语义一致性、长期审核项目和跨批次补件仍按 [文件集关联设计](Docs/DocumentSetDesign.md) 后续建设。

## 本地运行

新增功能操作见 [模板编写与模拟内审](Docs/Authoring.md)，包括参数联动、草稿版本、模型配置和当前边界。

中文操作手册见 [Markdown 版](Docs/UserGuide.md) 或 [可阅读和打印的网页手册](Docs/UserGuide.html)，包含本机实际端口、登录、上传预筛、规则说明和常见问题。

1. 安装 MySQL 8.4，并创建仅供开发使用的数据库和账号。数据库端口不要暴露给公网。
2. 将 `backend/.env.example` 复制为 `backend/.env`，生成并填写真实的 `CONFIG_ENCRYPTION_KEY`、`JWT_SECRET` 和本机 MySQL 连接串。真实 `.env` 不提交 Git。
3. 使用 `.python-version` 指定的 Python 3.12.10，在 `backend` 目录创建虚拟环境，并安装锁定文件 `requirements.lock`。
4. 先在独立 MySQL 8.4 测试库（建议名称 `iso13485_codextest`）验证初始化脚本；确认无误后，仅对空的开发数据库运行 `python InitDb.py`，再运行 `python CreateAdmin.py` 交互式创建管理员。切勿将正式库用作验证目标。
5. 在 `backend` 目录运行 `python Run.py`；监听地址与端口从 `backend/.env` 读取。
6. 使用 `.nvmrc` 指定的 Node.js 26.13.1，将 `frontend/.env.example` 复制为 `frontend/.env.development`，确认 API 地址，然后在 `frontend` 目录执行 `npm ci` 和 `npm run dev`。
7. 打开 `http://127.0.0.1:5300` 登录。端口以各环境 `.env` 中的设置为准。

初始化表命令只会为不存在的表创建结构，不会升级既有表。后续数据库结构变更须编写并审核迁移后应用；本次新增的 `uploaded_files.document_type` 在旧数据库上需要先按迁移说明添加字段。

## 端口清单

| 环境 | 前端 | 后端 | MySQL 示例端口 |
|---|---:|---:|---:|
| 本地开发 | 5300 | 8320 | 3406 |
| 测试/E2E | 5400 | 8400 | 3407 |
| 正式环境 | 5500 | 8500 | 仅内网访问，按部署配置 |

所有端口通过环境变量配置。前端变量只包含浏览器可见的 API 地址与页面配置；密钥和数据库凭证仅存后端环境文件。

E2E 另用 `.env.test` 的 `E2E_SMTP_PORT=5425` 启动本机隔离 STARTTLS 收件箱，不向外网发信。实际 SMTP 地址及端口由后端 `.env` 的 `EMAIL_SMTP_HOST` / `EMAIL_SMTP_PORT` 指定；它们是外部邮件服务，不是 MySQL 发信功能。

本机当前新版后端使用 8320，网页仍为 5300，MySQL 实际为 3306；表中列出环境示例的规划值。原后端 8300/8310 进程暂保留，新网页已通过前端环境配置连接 8320。实际配置和操作见使用手册。
